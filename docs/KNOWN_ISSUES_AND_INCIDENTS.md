# 已知问题与硬件排查指南 (Known Issues & Hardware Notes)

本文档记录在特定物理硬件与复杂打印场景下已知的边界现象与排查指南。

---

## 1. 打印机硬件脱机 / 卡纸导致的网络中断

* **现象描述**：
  在发生物理卡纸或机盖打开时，打印机内部会暂停网络模块或进入自检保护，此时客户端尝试连接会报错 `No route to host`，eSCL 扫描会返回 `JobCanceledAtDevice`。
* **边界说明**：
  * **网络直连的前提**：如果打印机硬件本身处于完全无法联网的物理故障状态（如未通电、强行断网、或硬件级报错挂起），软件层是无法跨越物理断网直接控制硬件的。
  * **排查指引**：发生卡纸或告警灯亮起时，请先手动清理机身卡纸，并按下打印机面板上的 **【OK 键】**。确认机身小屏幕上的 Wi-Fi 图标恢复常亮后，`printctl` 即可自动恢复通信。
  * **社区共建**：欢迎提交 Issue / PR 帮助我们一起探索更多硬件恢复阶段的自动重试与自愈机制。

## 2. 批量双面打印末页正面留白现象

* **现象描述**：
  在进行批量双面打印 14 页（7 张 A4 纸）时，最终拿到的纸张中，第 7 张纸表现为**“印有第 13 页正面的留白，背面就是结尾（第 14 页），中间没有夹带白纸”**。

## 3. 🚨 G3030 纯光栅机型：PDF/PNG 被静默丢弃，但命令报打印成功（2026-08-23）

* **现象描述**：
  Canon G3030 (G3833) 上 `printctl print` PDF 或 PNG，返回 `[+] Print job spooled successfully!`，但**无出纸、无报错、`Get-Jobs` 两头皆空**——打印机接受作业后静默丢弃。
* **根因**：
  该机型 `document-format-supported` 仅 `image/jpeg / image/urf / image/pwg-raster / application/octet-stream`，**无 PDF 解释器，PNG 亦不支持**。同机另发现：多文件批量默认 duplex 属性直接 `0x0507`（无双面器）；单作业槽忙时新作业同样报 `0x0507`。
* **详细报告与修复工单**：👉 [`INCIDENT_2026-08-23_G3030_FORMAT_SILENT_DROP.md`](INCIDENT_2026-08-23_G3030_FORMAT_SILENT_DROP.md)（含已验证 workaround、IPP 探测代码、BUG-1~3 验收标准）
* **临时规避**：用 `~/bin/bh-print`（Chrome→PDF→JPEG@220dpi→逐页重试进槽，实测 8/8 出纸）。

## 4. 🚨 G3030 4x6 照片打印：无尺寸声明被裁切，带 job-template 属性反而缩成角落（2026-08-25）

- **现象 A**：`--paper 4x6` 发裸 JPEG（1200×1800）→ 打印机按自有 DPI 假设放大裁切，相纸满幅但只显示约 1/3 图像。
- **根因**：JPEG 无物理尺寸信息，固件自行解释像素密度。
- **修复（已验证）**：JPEG 注入 JFIF APP0 密度标记 300×300 DPI（`injectJFIFDensity()`），画布 1200×1800 = 精确 4×6in，出图完整（面板需按一次 OK 确认纸张）。
- **现象 B**：在此基础上加 `media=na_index-4x6_4x6in` + `print-scaling=fit` job-template 属性 → 图片被按 ~600DPI 原样输出成 2×3in 小图贴在角落。
- **根因**：固件拿到这些属性后不缩放，属又一次"属性被静默误处理"（同 #3 的固件风格）。
- **修复**：已回退，作业模板属性一律不发（代码内有注释说明）。免面板确认未解决，疑需在机身设置关闭纸张确认提示。

### 2026-08-25 补充：4x6 竖版留白（letterbox）被固件"智能填充"破坏

本地导出验证发送的 JPEG 无误（1200×1800@300DPI，内容居中留白正确），但固件对相纸作业强制自动填充：纯白留白边 → 内容 bbox 放大 3 倍裁切（纸满、图剩 1/3）；浅灰(254)留白边 → 整张空白（疑似自动照片修正洗白）。**结论：JPEG 管线在 4x6 上只有"满幅旋转版"输出正确**（横图转 90° 铺满，横持相纸观看）。竖版留白需 PWG-Raster 自描述页面才可能实现，未验证。
