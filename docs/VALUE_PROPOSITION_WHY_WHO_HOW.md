## 1. 第一性原理推导 (First Principles Derivation)

从计算机硬件与信息论的第一性原理出发：

```
                    【物理现实世界】
                       ▲       │
       [物理喷墨还原]  │       │  [光电传感器采样]
                       │       ▼
 ┌─────────────────────────────────────────────────────────────┐
 │               【物理打印机 / 扫描仪硬件】                   │
 └─────────────────────────────┬───────────────────────────────┘
                               │
               (标准 HTTP / IPP 二进制字节流)
                               │
                               ▼
 ┌─────────────────────────────────────────────────────────────┐
 │                【printctl 极简抽象层】                      │
 │                                                             │
 │   1. 物理采样读取 (In)    : Scan()  -> Reader[Image/PDF]   │
 │   2. 物理光栅输出 (Out)   : Print() <- Writer[Image/PDF]   │
 │   3. 硬件状态遥测 (State) : Status() -> JSON[Health/Tanks] │
 └─────────────────────────────────────────────────────────────┘
                               │
                       (Unix Pipeline / API)
                               │
                               ▼
        【开发者 / Linux 脚本 / Cron 定时器 / AI Agent】
```

1. **扫描的本质**：是对物理纸张表面光信号的二维阵列离散采样，输出为数字位图流（`eSCL / HTTP GET`）。
2. **打印的本质**：是将数字位图流映射到物理 A4 画布点阵上，并驱动微喷孔喷射墨水（`IPP / HTTP POST`）。
3. **驱动与中间件的本质**：只是做**几何规整（坐标与边距映射）**和**协议组装**。
4. **推论**：任何强加在用户身上的庞大桌面 GUI、系统级守护进程（CUPS/SANE 几百兆内存占用）、厂商私有闭源驱动，**在数学和协议层面全部是非必要的冗余（Accidental Complexity）**。

## 2. 服务区间与能力边界定义 (Service Boundary & Scope)

为确保系统职责极其清晰、零外部纠缠，我们明确界定本工具的**前置条件与服务边界**：

```
 ┌──────────────────────────────────────┐     ┌───────────────────────────────────────────────────────┐
 │       【前置物理准备区间 (Prerequisite)】     │ ──> │               【printctl 核心服务区间 (Our Scope)】    │
 ├──────────────────────────────────────┤     ├───────────────────────────────────────────────────────┤
 │ 1. 拆箱与撕除胶带                    │     │ 1. 局域网毫秒级设备自发现 (Zero-Config Discovery)     │
 │ 2. 安装 C/B 打印头与灌注墨水         │     │ 2. 图像智能规整与防翻车排版 (Alpha拍平/边距/防截断)   │
 │ 3. 完成硬件初始化充墨                │     │ 3. 纯 Linux 免驱直连打印 (IPP Everywhere 直传)        │
 │ 4. 首次配网（Wi-Fi 或网线进入局域网）│     │ 4. 纯 Linux 免驱高清扫描 (eSCL 75~600 DPI 直拉流)     │
 │ 5. 任何设备完成第一次握手验证        │     │ 5. 硬件状态与耗材余量遥测 (JSON 标准输出)             │
 │                                      │     │ 6. 面向 Bash / Python / AI Agent 的无头标准 I/O 管道  │
 └──────────────────────────────────────┘     └───────────────────────────────────────────────────────┘
```

> **服务分界点**：
> 一旦打印机通电并连入您的本地 Wi-Fi / 局域网，**从这一秒起，所有在 Linux / Unix 环境下的打印、扫描、监控与自动化调度，全部由 `printctl` 提供纯粹、极致的无头免驱服务。**

## 3. WHY：为什么存在 (The Core Problem & Value)

### 痛点对比矩阵

| 传统 Linux / 厂商方案的痛点 | `printctl` 的第一性原理破局 |
| :--- | :--- |
| **驱动黑洞与碎片化**：Linux 下厂商驱动常年断更或缺失，装一个驱动要配几十个老旧 32 位依赖。 | **标准协议通杀**：基于 IPP Everywhere 和 eSCL 行业公开标准，单文件通杀佳能、惠普、爱普生、兄弟等 95% 现代网络机型。 |
| **打扫割裂**：扫描要装 SANE/`sane-airscan`，打印要装 CUPS，两个庞然大物彼此不通。 | **单文件一体化 (All-in-One)**：一个 5MB 的静态 Go 二进制，同时囊括打印、扫描、状态和自发现。 |
| **系统侵入性大**：必须开 root 权限跑 `systemd` 后台服务，占用数百兆内存。 | **零安装、零守护进程 (Zero-Daemon)**：无常驻后台、无特权要求，随调随走，0 内存残留。 |
| **图片打印频频翻车**：透明图打成大黑底、多吐一张白纸、横屏照片被截断。 | **防御性数学规整**：内置 Alpha 拍平算法、5mm 物理硬件安全边距、自动纵横比识别，数学上杜绝翻车。 |
| **无法自动化与 AI 集成**：传统方案全是写给人用鼠标点的桌面 GUI，脚本无法操控。 | **Agent / Pipeline 原生**：像 `curl` / `ffmpeg` 一样支持标准输入输出，AI 调一行命令即可操控物理世界。 |

## 4. WHO：为谁而生 (Target Users & Personas)

1. **Linux 极客与无桌面服务器用户 (Headless Server Users)**：
   在 Ubuntu Server、Debian、Arch、Alpine Linux 上需要最纯粹、零依赖的打印扫描工具。
2. **软路由 / NAS / 树莓派玩家 (Homelab & Embedded)**：
   运行在 OpenWrt、群晖、TrueNAS、Raspberry Pi 上，作为全天候家庭打印/扫描微网关。
3. **AI Agent / 自动化工程师 (AI & Automation Developers)**：
   需要让 LLM（DeepSeek / Gemini / Claude）具备物理视觉感知（自动扫描纸张）与物理输出（自动打印解答）的开发者。
4. **Paperless-ngx / 自动化办公流程搭建者**：
   需要定时或一键将纸质发票、合同无损拉流归档为本地 PDF/JPG 的极简主义者。

## 6. 技术规范与工程承诺

* **语言选型**：纯 Go (Golang) 编写，`CGO_ENABLED=0` 静态编译。
* **分发形态**：单可执行二进制文件（跨架构支持：Linux x86_64, Linux ARM64, macOS, Windows）。
* **协议遵循**：
  * RFC 8010 / RFC 8011 (Internet Printing Protocol 2.0 / Everywhere)
  * Mopria Alliance eSCL Specification v2.9
  * Apple AirPrint / PWG Raster
* **维护性承诺**：协议已冻结 15 年，代码逻辑收敛于标准数学模型，一次编写，十年免维护运行。
